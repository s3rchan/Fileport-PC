# Fileport PC v1.8 — GitHub Releases update integration

## Windows update controls

Open **Settings → GitHub updates (Windows)**. Click **Check for updates** to query this repository's public Releases, then **Download and install** to download the newer NSIS installer. The previous **Offline update → Select update file** remains available. Android is not modified. Local Wi-Fi file transfers still require no internet.

The updater only accepts a stable public `pc-vX.Y.Z` release published in `s3rchan/Fileport-PC-v1.6`, containing exactly one `Fileport_X.Y.Z_*_setup.exe` NSIS installer (generated by Tauri) with GitHub-provided SHA-256 digest. Download size, version and SHA-256 are checked before execution. If the running Fileport EXE is Authenticode-signed, the replacement must have the same publisher certificate. **Unsigned GitHub development builds do not provide publisher authentication**; the application warns before downloading. For production releases, use an Authenticode code-signing certificate and protect GitHub repository access with 2FA.

## Publishing updates

1. Commit the complete v1.8 source to the repository (including `.github/workflows/build-windows.yml`).
2. Use GitHub **Actions → Build Fileport Windows EXE → Run workflow** for build tests and Artifacts. This action alone does **not** publish a release.
3. In GitHub select **Releases → Draft a new release**, create tag `pc-v1.8.0` from the latest commit, and publish. The tag push triggers Actions; after a successful build it uploads the NSIS `.exe` to the corresponding Release automatically.
4. Future `pc-v1.9.0` builds (with app version updated to `1.9.0`) will be found by a running v1.8 client. Already-installed v1.7 clients cannot check GitHub because that feature is new; install v1.8 once.
5. Publish only after tests pass. If Actions or release upload fails, inspect logs and do not distribute the release.

**No release currently exists on this GitHub repository**, so update check will report that until the first release is published.

## Development

Run `npm install`, `npm test`, and `npm run build -- --bundles nsis` in an environment with Rust, Windows Build Tools and WebView2. CI on GitHub uses `windows-latest`. Native Windows update download and installer launch must be verified on actual Windows hardware; this environment performs source and JS checks only.
